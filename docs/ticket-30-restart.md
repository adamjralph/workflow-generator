# Ticket 30 — committed Gate pause restart candidate

**Status:** implementation candidate, not independently reviewed or accepted. The accepted D2 contract and ADR 0012 remain authoritative. This is offline, Linux/CPython/bubblewrap only; it does not establish exactly-once execution for arbitrary side effects.

## Public path

1. Emit a restricted version with `emit_gate(spec, operations, store=external_owner_only_path)` and start an operator run via `start_gate(version, run_id=...)`. Its context manager must close after the `PENDING` result and committed two-envelopes-per-visited-node prefix ending at the Gate. The retained executable worker is not regenerated from the caller's code.
2. Use `python -m agent_lab.gate_cli --store ... --run-id ... inspect` and the explicitly scoped `approve` or `reject` action. The decision file is owner-only and HMAC-bound to the exact checkpoint; same-UID processes share this authority.
3. In a fresh Python process, call `with recover_gate(store, run_id=...) as run:` and read `run.result` / `run.attestation`. Recovery uses retained version bytes, the original driver, exact committed pause, scoped decision, and a nonblocking exclusive per-run file lock. It has no caller-supplied state, entry node, executable binding or approval. The new worker reconstructs the chain and continues the original route.
4. `check_gate_restart(spec, operations, version, cases)` compares hand-authored expected pending/final observations and retained journals for separately decided reference and graph workers across a worker restart. The public subprocess test additionally exercises a distinct Python controller process.

## Commit and recovery boundary

The worker publishes each canonical numbered envelope by exclusive temporary file, file fsync, no-replace link, directory fsync, temporary unlink, then directory fsync again. It acknowledges only afterward. The Gate checkpoint and pending event share the final envelope of the pause prefix, with a proof over the committed prefix. The local operator CLI publishes and reads back `decision.json` before recovery; a linked decision whose directory sync fails retains a `.pending-*` ambiguity marker. The retained worker takes the CLI's operator-key file lock and checks for ambiguity markers immediately before consuming the decision, including an already-open same-process worker and a recovery that inspected before concurrent submission. On recovery, the host validates the full semantic pause prefix and re-derives spec, operation and bundle bytes under the exclusive claim; the retained worker independently verifies the prefix/proof and the decision before journaling `decision`, then `resolved`, then any downstream `claim` and `completed`. Both drivers retain their independent schedulers.

Only an untouched, semantically verified committed pause prefix (two envelopes per visited node, ending at the Gate) plus a valid decision is eligible. An orphan `.pending-*`, missing/truncated/extra envelope, committed decision without resolution, resolution without downstream completion, or in-flight downstream claim is **indeterminate** and requires explicit resolution/new run. No automatic repair or replay. A `crash_at=(sequence, boundary)` option is an explicit deterministic offline fault-injection hook; boundaries are `before_file`, `after_file`, `after_link`, `after_dirsync`, `after_unlink`. For the three-node specimen, a crash at sequence 4 before file creation leaves the same untouched pause eligible; later boundaries and all subsequent sequences refuse replay. It deliberately never interprets a linked-but-unacknowledged record as permission to retry. The first directory fsync precedes temporary unlink, so a missing temporary after a crash cannot mean the numbered link was never durably committed.

This is an OS-account trust boundary, not protection from a malicious same-UID actor replacing the trusted verifier or using the key. No live model, tool effect, Fork Gate or arbitrary mid-step exactly-once behavior is admitted. Recovered versions must contain the ticket-30 retained worker; older ticket-29 bundles do not gain a new recovery capability by changing ambient source.
