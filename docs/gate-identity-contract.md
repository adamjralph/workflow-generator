# D2 contract — executable identity, human Gate and continuation

**Status: accepted decision contract, 2026-09-25.** Adam gave blanket approval to the recommendations and specifically approved the local OS-account operator boundary. This narrows P17 in the [delivery map](../.scratch/workflow-generator/map.md#p17--gate-and-exact-executable-identity-together). It does not choose a public persistent spec format or change ADRs 0004/0005/0009. **Contract acceptance is not a completed Gate implementation, tested security guarantee, commit or push.** If an implementation cannot meet a clause, stop and bring the trade-off back rather than silently claiming a weaker digest is exact executable identity. See [ADR 0012](adr/0012-gate-identity-and-local-operator-continuation.md).

## Fixed boundaries and present gap

- ADR 0005 requires approval of **both** re-derived spec and emitted-bundle digests. ADR 0009 requires immutable, digest-addressed artifact versions; ADR 0002 keeps writes outside Hermes. ADR 0004 leaves public serialization undecided. The plain driver is the reference for conformance (ADR 0008).
- `GateNode` is admitted with `approved`, `rejected`, `pending`, `invalid` routes (`agent_lab/spec.py:64-69`), but `compile_reference` rejects it as unsupported (`agent_lab/reference.py:279-347`); `generate_graph` asserts an executable node is one of Transform/Decision/Judgment/Loop (`agent_lab/generation.py:234-273`). Neither driver/checker currently proves Gate behavior.
- Today's graph candidate seals its owned structure and snapshots mapping **containers**, not the behavior or transitive dependencies of caller-owned Python callables (`agent_lab/generation.py:234-273`). `inspect_structure()` does not attest binding code (`:74-88`). The existing foundation draft approval binds run/draft, **not** this spec/bundle pair. `RunLog.fresh_run()` explicitly refuses reuse of an already recorded run ID; it is not a restartable continuation (`agent_lab/runlog.py:38-124`). Do not reuse these seams as proof of P17.

## Accepted bounded contract

1. **Private identity representation.** Define a versioned, canonical *internal* encoding of the admitted `WorkflowSpec` (including entry, ordered nodes/edges, routes, budget and terminals), with domain separation and explicit encoding version; hash its bytes. Freeze those exact bytes in an immutable per-workflow artifact version. This is an internal identity protocol, not a user-facing import/export spec format or a community/packaging decision. Re-derive from retained bytes at every Gate and resume; compare against the currently admitted spec, never an asserted digest field. Invalid, unknown-version or noncanonical encodings fail closed. A regenerated spec, even at the same path, is a new version if bytes change.
2. **Executable bundle identity.** The bundle is a retained, reproducible executable *manifest plus artifacts*, not merely the graph drawing or a Python object ID. It includes the internal spec digest, target/emitter version, deterministic graph execution configuration, state schema, selected binding keys and a verified immutable identity for all executable binding implementations/configuration and their required dependency closure. Hash canonical manifest bytes and referenced artifact bytes; re-derive before approval and continuation. No path, `repr(callable)`, import name alone, caller-supplied digest or mapping proxy constitutes proof of callable behavior. Mutable closure/global state and dynamic loading cannot honestly be made exact by hashing a function's source alone. A changed code/config/dependency artifact or unverifiable binding **requires a new bundle or refusal**, never inherited approval. The first Gate slice must explicitly restrict what bindings it admits; see decision A.
3. **Approval scope and trust.** A decision is a durable record scoped to `(workflow identity, immutable version, run ID, Gate node ID, pause/attempt ID, spec digest, bundle digest, decision, local OS account, recorded time)`. The first slice uses an owner-only **local operator CLI**, invoked explicitly under the OS account, with owner-restricted artifact/approval store access. The CLI derives the local OS-account identity itself; it does not accept a caller-supplied approver string as proof. Its operator action is auditable and distinct from offline fixture decisions. **This trusts the OS account, not a unique human:** another agent or process with the same UID can submit a decision; it is not safe to claim person-level authentication. Do not expose this approval operation to a remote caller or general agent tool without a new trust design. An approval or rejection applies once to that exact pause, not to all runs of the same bundle or to a later visit to the same Gate. The service re-derives both digests from stored artifacts and validates the paused run/Gate/attempt before recording or consuming a decision. Repeated identical submissions are idempotent; contradictory or late decisions fail. No approval can be inferred from an existing business-draft receipt.
4. **Gate routes, continuation and budget.** A Gate visit consumes **one** run-wide step only when it is reached; a short budget fails before unrecorded downstream work. `pending` is a durable pause with no transition to downstream work. A valid `approved` decision permits only its declared approved route; `rejected` stops the run and never unlocks an alternate downstream action; an invalid/stale/forged decision is a recorded fail-closed terminal or refusal, never an approval. The declared `rejected`, `pending`, `invalid` Gate labels describe observable outcomes, not permission to execute arbitrary successor nodes; executable P17 Gate routes must obey these restrictions. Decision submission and continuation charge **zero additional steps** for that already charged visit. At a Gate, persist a typed, versioned checkpoint containing the exact post-completed-step state, Gate/pause identity, used and remaining run-wide budget, completed event-chain head and both artifact identities. Resume has no arbitrary entry or caller-reconstructed state: it loads the checkpoint and decision, rechecks all identities and event continuity, and advances only the remaining work through reference and generated drivers. Repeated resume cannot repeat prior work or charge it twice. Both drivers must yield the same canonical events and budget accounting, while their approval inputs are independently supplied offline during checking. The exact event schema and write ordering must be specified and tested in implementation, not inferred from this paragraph.
5. **Restart and audit boundary.** P17 promises **restart after a durably committed Gate pause**, not exactly-once side effects across an arbitrary mid-step process crash. Persist artifacts, checkpoint, decision and an append-only event chain in the user-named store with atomic commit/recovery rules and a per-run exclusive continuation claim. After a process restart, reconstruct from that evidence rather than in-memory Python objects; a missing, torn, corrupt or ambiguous checkpoint/decision/log fails closed. A crash while a step is in flight is indeterminate and is not replayed automatically; otherwise side effects may repeat. Specify and test the ordering/atomicity of event, checkpoint and decision writes and crash injection cases before claiming this guarantee is implemented. On audit write failure, do not emit successful continuation or execute downstream work.
6. **Limits.** Start with one Gate on a non-parallel Route workflow; no Gate inside a Fork, no between-wave Gate (P18), no regeneration/user-layer merge (P19), no live model/tool side effects, no Hermes writes, no general arbitrary-Python portability claim. P17 should still be a complete visible pause → human decision → checked continuation slice, not an identity-only ticket declared to deliver Gate support.

## Decisions accepted and explicit limitations

**A — Binding:** admit only a small registered, deterministic, no-external-side-effect operation set whose code/config/dependency artifact is frozen and hash-verified in the store; reject arbitrary closures, mutable globals and unpinned dependencies. The registry's build/install and post-restart resolution rules need concrete design and tests. This is *not* yet true of today's caller mappings. A qualified name or source hash alone does **not** meet ADR 0005.

**B — Restart:** recovery only from a fully committed Gate pause; an indeterminate in-flight step requires explicit resolution/new run, not blind replay. Arbitrary-crash exactly-once is out of P17.

**C — Accounting:** charged once on Gate visit; pending pauses; decision/resume costs no new step; approved follows its route, rejected terminates, invalid fails closed. One-use run/Gate/pause decision.

**D — Approver trust:** owner-only local CLI under the OS account, as specifically approved by Adam. This is account-level trust, not person-level authentication; offline fixture decisions do not authorize a real run. If same-UID agents must be excluded, this boundary is insufficient and needs a new decision.

## P17 acceptance evidence for later vertical slices

1. Hand-authored expected states/events/spend for Route → Gate → Route. Pause, explicit reject, and approved continuation through **both** independent drivers; checker observes the actual emitted artifact with independent fixture decisions.
2. A fresh process reads the retained immutable version and committed pause and completes once; a second resume yields no new step/event/effect. Exact spent/remaining budget and state survive restart. Audit-write and crash-boundary injection have declared outcomes.
3. Changed spec, bundle, binding bytes/config/dependency, run ID, Gate ID or pause attempt cannot inherit approval. Altered candidate, forged digest/decision/continuation, stale or double decision, missing/corrupt evidence and audit failure fail closed **before downstream work**.
4. Conformance compares the reference with the generated driver, including pause/reject/resume event chain and independently supplied offline approvals. It does not infer semantic quality, Python callable purity, approver identity from a string, or provider authenticity.

**Next gate:** plan complete vertical slices and a public test seam/review baseline, then seek an explicit go for a bounded implementation ticket. Approval of this contract is not proof that the artifact/OS-account trust boundary works, and does not itself authorize a live call, agent delegation, commit or push.
